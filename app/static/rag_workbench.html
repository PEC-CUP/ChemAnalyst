RAG manual

What this page does

This workbench evaluates the current petroleum literature knowledge base with the three main manuscript-facing RAG routes and exposes request-time retrieval overrides for controlled comparison. It is for route testing and KB inspection, not for editing the core synthesis logic.

QA-oriented RAG

This is the main factual question-answering route. It combines broader evidence recall, evidence filtering, and document-level organization to produce evidence-grounded answers for petroleum-domain QA tasks.

Naive RAG

This is the direct retrieval baseline. It is useful for simple questions and route comparison, but it may miss sufficient evidence for broader synthesis tasks.

Iterative Review RAG

This route extends QA-oriented retrieval with iterative evidence review and supplementary retrieval. It is intended for questions that require broader evidence coverage or multi-document synthesis.

Route comparison

Run selected mode tests one route. Compare all RAG routes runs the same question through the three main routes so that evidence recall and synthesis differences can be inspected under the same query condition.

Retrieval overrides

Query refinement, BM25 fusion, and reranker settings are request-time overrides. They are mainly for ablation or debugging. Leave them as default when reproducing the current paper-facing settings.

KB pipeline panel

The lower panel is for petroleum KB maintenance actions such as source scanning, ingest, chunking, and index building. These actions write KB artifacts and should not be run casually during evaluation.

Output boundary

This page changes request-time retrieval behavior and can trigger KB maintenance actions, but it does not redefine the underlying route implementations.

1. RAG query test

Run the same petroleum-literature question through one or all RAG routes. For paper-like tests, keep overrides at default.

Choose one of the three main RAG routes used in the manuscript. QA-oriented RAG is the default factual route, whereas iterative review RAG performs evidence sufficiency checking and supplementary retrieval.

Enter the same petroleum-domain question when comparing routes. This allows retrieval differences and evidence-processing differences to be inspected under the same query condition.

Override whether the route first rewrites or expands the original question before retrieval. Leave as default unless you are testing the effect of refinement on evidence recall.

Override whether keyword-based BM25 retrieval is fused with semantic retrieval. This is useful for checking whether lexical recall improves evidence coverage for narrow factual questions.

Override whether a reranker reorders the retrieved candidates before synthesis. Disable this only when isolating the contribution of candidate ranking quality.

Interpretation: use selected-mode testing for debugging one route; use compare mode to inspect whether QA-oriented or iterative review RAG recovers evidence that naive RAG misses.
