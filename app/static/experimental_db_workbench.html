Experimental Database manual

What this page does

This workbench manages sample-centered historical experimental records and tests the historical-neighbor evidence workflow used for training-free property inference. It separates persistent database import from transient query evidence testing.

Sample-centered records

Each imported record is keyed by sample_id and can retain sample information, bulk properties, analysis rows, relations, artifacts, and provenance. The goal is to keep each historical sample as one traceable database object rather than as scattered files.

Import and storage

Excel workbooks are the normal import path. Imported content is written into sample records under samples/ and indexed through registry files and catalog/experimental_samples.sqlite for browsing and search.

Sample Manager

The separate Sample Manager is the maintenance interface for browsing, filtering, supplementing, and deleting persistent database records. Use this workbench when importing new records or running evidence tests.

Feature extraction path

The evidence test converts available analysis data into comparable features before neighbor retrieval. Tabular properties can be used directly, while supported GC-FID or IR data follow the embedded featureization path already configured in the current implementation.

Historical-neighbor retrieval

The evidence test compares the query sample with historical records in a shared feature space and returns the top-k nearest historical samples after weighted ranking. The query workbook remains transient during this process and is not inserted into the database automatically.

Training-free property inference

No dedicated property regressor is retrained during the test. Retrieved neighbors are summarized into evidence ranges, weighted evidence centers, and supporting sample lists, which can then be interpreted with optional LLM analytical reasoning.

Evidence output

The returned output is a structured evidence package for inspection, manuscript use, or downstream comparison. It includes the query profile, retrieved neighbors, property summaries, and raw JSON evidence rather than only a single final number.

Template governance

The active Excel template defines the current import structure. Template update is an advanced governance path for redefining laboratory-specific sheets and fields and should be used only when the database schema itself needs to change.
