Analytical Tool Onboarding

Package a reviewed analytical data-processing script as a ChemAnalyst capability. The default hydrocarbon-type calculator is a complete onboarding example; advanced schemas are generated from the preset and can be inspected only when needed.

Analytical Tool Onboarding manual

What this page does

This workbench packages a reviewed analytical script, callable function, or service endpoint as a ChemAnalyst capability that can be invoked through the planner workflow. The expected output is structured tool evidence and optional downloadable artifacts.

Current page structure

  • Tool identity and example: choose a preset and define the Planner-visible name and description.
  • Runtime adapter: define how the reviewed executable is called and how output is parsed.
  • Onboarding actions: prepare, deploy, check, or revoke a provider package.
  • Runtime test: send a planner-routed query and uploaded workbook through the current runtime path.

Hydrocarbon-type example

  • Hydrocarbon type composition is the complete runnable onboarding example in the current release and deploys as tool.hydrocarbon_type_calculator.
  • It shows the full route from reviewed script packaging to planner-visible execution and artifact return.
  • The preset is editable and can be used as a starting point when onboarding a new reviewed analytical tool.

Invocation type

  • python_script: wraps an existing external .py file through an adapter.
  • python_callable: imports and calls a reviewed internal function, typically under app.tools.*.
  • http_api: calls a reviewed service endpoint.
  • manual: registers metadata only and does not execute automatically.

Runtime adapter and config

  • The adapter is the execution bridge between the planner-selected tool and the reviewed executable target.
  • It maps uploaded inputs, calls the executable, parses the returned result, and formats structured evidence for the runtime.
  • Adapter config JSON is an advanced executable contract; routine users normally keep the preset value unless adapting a new tool.

Input template workbook

  • Each provider can carry a runnable input template that matches its expected workbook structure.
  • After uploading a template, prepare or deploy the provider so the template is copied into the provider package.
  • The runtime can then expose that template when planner-selected execution requires user input.

Planner-routed runtime test

  • The test conversation first sends a natural-language query to the planner.
  • If a matching registered tool requires an input workbook, the runtime returns an input request and template link.
  • Uploading a workbook sends the file through the current execution path and returns structured tool evidence.
  • A follow-up query can ask the planner to read and interpret that returned evidence.

Safety and review boundary

  • Prepare package writes the provider package files but does not enable execution.
  • Deploy to Planner saves, marks reviewed/enabled, and registers the provider in the current runtime.
  • Check selected provider audits package structure and reviewed adapter availability.
  • Revoke selected provider disables and unregisters a provider while keeping package files for audit and reuse.

2. Runtime adapter

The adapter is the executable bridge. For this example, ChemAnalyst calls a reviewed hydrocarbon type composition Python function with an uploaded workbook path and an output folder path.

Runtime call steps: choose how ChemAnalyst calls the tool, resolve the reviewed script/callable/API, bind the uploaded workbook to the adapter input, execute the function, parse the generated output, and return structured tool evidence plus downloadable artifacts.
Invocation type tells ChemAnalyst what kind of executable target is being wrapped. Use python_script for an external script file, python_callable for a reviewed function under app.tools.*, and http_api only for a reviewed service endpoint.
Generic adapter template defines the calling convention. The current hydrocarbon example uses generic_python_function, which loads the script, calls a named function, sends input/output paths, and parses the result file.
