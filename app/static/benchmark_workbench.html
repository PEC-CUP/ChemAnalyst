KB Construction and QA Generation Workbench

Build staged literature knowledge bases and keyword graphs for inspection, and generate evidence-conditioned QA benchmarks without changing the active RAG knowledge base.

KB construction and QA generation manual

What this page does

This workbench has two linked but separate functions: staged petroleum literature knowledge-base construction and QA benchmark generation. The first prepares or inspects literature evidence resources, whereas the second generates evaluation datasets from those resources without changing the active RAG runtime by default.

Staged KB construction

The KB panel runs PDF parsing, scientific chunking, cleaning, embedding-index construction, and optional keyword-graph generation as a staged build under outputs/kb_construction. This page is mainly for safe inspection of newly added literature before any manual production update.

Active KB and keyword graph

Refresh KB status checks the active clean chunks, active index, and active keyword graph. Open active keyword graph opens the current production graph for corpus-level inspection. Staged graphs are generated separately and should be inspected before replacing any active resource.

QA source modes

Existing processed chunks uses the current cleaned KB source and is the normal route for reproducing benchmark datasets from the active literature resource. PDF directory first processes a separate PDF set and then generates QA from those newly prepared documents without overwriting the active KB.

QA benchmark types

The preset routes cover the current paper benchmark types: reviewed single-document semantic QA, reviewed two-document semantic QA, specific-fact open QA, specific-fact MCQ, and naive baseline datasets. These types support evaluation of evidence localization, cross-document synthesis, narrow factual retrieval, and controlled factual verification.

Reviewed and baseline modes

Reviewed applies quality audit, duplicate control, and revision gates before writing accepted QA items. Naive baseline keeps a weaker generation route for comparison and should be treated as a construction baseline rather than a paper-grade benchmark.

Output boundary

Running this page creates or updates staged KB artifacts and benchmark JSONL datasets only. It does not by itself change the active RAG route definitions, planner logic, or evaluation code.
